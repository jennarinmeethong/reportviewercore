# DecisionLog

## Decisions

- Cross-platform v2 uses .NET 10 and a backend-neutral rendering boundary. SkiaSharp provides drawing/image/PDF surfaces and HarfBuzzSharp provides OpenType shaping on Windows, macOS, and Linux. WinForms remains a Windows display adapter; legacy GDI, Uniscribe, printing, TIFF, and EMF stay isolated in the compatibility line until explicitly migrated.
- The migration is incremental: establish and test the portable rendering slice before rewiring the legacy ReportViewer engine. Existing packages are not described as cross-platform-safe yet.
- The headless v2 seam accepts a backend-neutral `ReportDocument` and injected `IReportRenderer` implementations. `LocalReport` now owns the constrained RDLC-to-document workflow, while `ServerReport` only delegates to an injected transport; neither exposes GDI types or implicit Windows credentials.
- HTML is initially emitted as standalone SVG-backed markup so text, links, and images remain inspectable without a browser runtime. Hyperlinks are scheme-validated; PDF hyperlink annotations remain a separate backend task.
- OpenXML starts as a managed text/hyperlink baseline using direct OPC zip parts. Unsupported shapes/images fail explicitly rather than being silently dropped; this keeps the RPL/SPB mapping gap visible.
- The first portable engine slice deliberately supports a constrained RDLC subset (multiple offset tablixes, mixed images/shapes/bar/column/line/area/pie charts, enumerable row binding, and field/parameter value expressions). It produces the backend-neutral document before broader RDL features are migrated.
- The public v2 local API is intentionally separate from legacy `Microsoft.Reporting.NETCore.LocalReport` until feature parity exists. Remote rendering requires an injected transport, making authentication explicit on macOS/Linux.
- The legacy .NETCore API gets an explicit net10-only `CreatePortableDocument`/`RenderPortable` bridge. It reads the direct definition/data sources without calling the legacy rendering session, preserving v1 `Render` behavior and making migration opt-in. `SetPortableParameters` is separate because legacy `SetParameters` retains its original validation/session semantics.
- The same opt-in bridge is available on the net10 WinForms `LocalReport`, and `PortableReportViewer` consumes the shared `ReportDocument`. A Windows smoke sample exercises this path so Windows uses the same Skia backend as other platforms.
- Subreports are resolved by an injected `IRdlcSubreportResolver`, reuse the same engine/context, support explicit parent-to-child parameter mappings, and are capped at eight nesting levels. No implicit file/network lookup is performed.
- `HttpReportServerTransport` uses SSRS URL access over an injected `HttpClient`; authentication is an `IReportServerAuthenticator` callback, never default Windows credentials. Format and report parameters are encoded into the request URI.
- Bar, column, line, area, pie, and doughnut charts emit native XLSX and DOCX chart XML through DrawingML relationships; semantic text is also retained for accessibility/compatibility.
- Fixture-driven aggregate tests now include `Min` and `Max`, and fixture-driven OpenXML tests parse every generated XML part in XLSX/DOCX archives before relying on semantic content assertions.
- RDLC embedded images resolve through `IImageResolver`; the engine remains backend-neutral and Skia normalizes decoded images to PNG. HTML, PDF, XLSX, and DOCX consume the same `RenderImage` operation. External image fetching remains an explicit resolver responsibility.
- Image values use the same parameter/field expression path as text before resolver lookup. This supports dynamic image keys without adding filesystem or network access to the engine.
- Tablix-cell images use the existing `PlacedImage` contract with cell-column and repeated-row offsets. No tablix-specific renderer API was added, so HTML/PDF/OpenXML/Windows can consume the same image operation.
- Mixed body content is merged after tablix row expansion into the same text/image/chart/shape lists. This avoids introducing a second rendering path and prevents standalone report items from being dropped when a body also contains a tablix.
- The legacy `DrawBarChart` entry point remains a compatibility shim while the backend-neutral `DrawChart` contract carries bar, column, line, area, and pie semantics. Skia/HTML render those shapes and OpenXML emits matching native chart parts plus semantic title/label/value content.
- The constrained RDLC engine rejects explicit `Radar` and other unsupported chart types; accepting them as bars would silently change report meaning.
- Skia PDF hyperlinks use native URL annotations over the shaped text bounds; URL schemes remain constrained to relative, HTTP(S), and mailto values.
- Vertical text is represented by the shared `TextDirection` contract: Skia emits vertical glyph advances, HTML uses SVG writing mode, Word OpenXML emits `w:textDirection`, and Excel emits native cell alignment styles for vertical, reverse-vertical, and RTL directions.
- RDLC page headers and footers are modeled as repeating page-relative text decorations. They are applied after content pagination so both textbox and tablix reports repeat them on every output page.
- RDLC report parameter defaults are applied at document creation into a case-insensitive parameter map; caller-supplied values always win, and multi-value parameters are exposed only through the allow-listed `Join(Parameters!Name.Value, separator)` expression.
- RDLC textbox hyperlinks are carried as optional text-placement metadata so the same report action reaches HTML anchors, PDF URL annotations, and OpenXML relationships without exposing backend types in the engine.
- OpenXML hyperlink emission applies the same relative/http/https/mailto allow-list as Skia/HTML; unsafe schemes are rejected before OPC relationships are created.
- The hyperlink allow-list lives in `ReportViewerCore.Rendering.Abstractions` and is reused by Skia, HTML, and OpenXML so backend security behavior cannot drift.
- Nested rectangles are traversed recursively in the constrained engine, accumulating parent offsets for child text, images, charts, lines, and shapes; this keeps the backend-neutral page model absolute.
- RDLC text `Style.Color` and `Style.WritingMode` are mapped to placement metadata. The backends remain responsible for their native representation, preserving one engine contract for color and direction.
- The constrained expression host supports quoted literals and top-level string concatenation with `&`, in addition to direct field/parameter values. Unsupported expressions remain empty rather than invoking arbitrary report code.
- Basic `FillRectangle`, `DrawRectangle`, and `DrawLine` operations are preserved in OpenXML: Excel uses DrawingML shape parts, while Word uses a VML compatibility fallback. This closes the basic-shape gap without pretending advanced vector/RPL parity exists.
- OpenXML line shapes retain their original start/end points internally; Excel emits DrawingML flips and Word emits VML `from`/`to` points so reverse-direction lines do not collapse to a bounding-box diagonal.
- DOCX text preserves the backend-neutral horizontal baseline offset as a Word paragraph left indent in twips; vertical/floating absolute layout remains deferred until the document model can represent it without cumulative paragraph-spacing errors.
- DOCX inline image and chart paragraphs use the destination X as the same left indent policy; destination Y and true floating anchors remain deferred.
- `IReportPageSource`/`ReportPageSourceAdapter` is the portable RPL/SPB seam. It accepts already-paginated pages and renders them into the shared document; the adapter deliberately does not reference v1 internal RPL types so the portable packages remain cross-platform.
- The constrained expression host adds `IIF`, simple comparisons, and numeric/date `Format` over the existing field/parameter/concatenation support. Unsupported functions remain non-executable until a full secure expression-host design is approved.
- The constrained expression host also allow-lists `IsNothing` for field/parameter null checks and boolean `Not`/`And`/`Or` composition; unsupported null operands resolve empty and never broaden into arbitrary expression evaluation.
- Direct tablix `SortExpressions` are evaluated against each data row before pagination; multiple expressions preserve stable ThenBy ordering, with numeric comparison when both values parse as numbers.
- The constrained aggregate host supports tablix-scope `CountRows()`, `Sum(Fields!...Value)`, and `Avg(Fields!...Value)`. It materializes the sorted row scope and does not expose arbitrary dataset traversal to body expressions.
- The constrained aggregate host also supports numeric `Min(Fields!...Value)` and `Max(Fields!...Value)` over the same group scope; culture-formatted output remains renderer-independent text.
- The first row-group seam reads one `TablixRowHierarchy` group expression and partitions sorted detail rows before rendering. It intentionally stops short of nested group members, group headers, subtotals, and recursive grouping until the page model supports those structures explicitly.
- First-level grouped tablixes may render a middle row template once per group as a group header, followed by the final detail template. Nested group members, subtotals, and recursive group layout remain explicit future work.
- First-level grouped tablixes with a fourth row template render that final template once per group as a subtotal/footer, using the same group scope. This is intentionally a constrained row-template convention, not a claim of nested SSRS member parity.
- Multiple `GroupExpression` values are combined into an ordered composite scope key before group header/detail/footer rendering. Nested visual member trees remain out of scope until the page model can represent them directly.
- With two group expressions and five row templates, the engine maps templates as static header, outer group header, inner group header, detail, and footer. This is an explicit two-level compatibility slice rather than arbitrary recursive member inference.
- Nested row-group support generalizes that convention to three or more ordered group expressions: each prefix scope gets one matching header template, followed by detail and optional footer templates. Arbitrary `TablixMember` trees and page-break semantics remain separate work.
- Constrained grouped page breaks are applied between materialized composite scopes by advancing the accumulated row offset to the next page boundary. This keeps page-break behavior deterministic without claiming full SSRS member/page-layout parity.
- Grouped page breaks are tracked at the member's flattened expression level and only advance when that scope prefix changes; a break on an outer group must not fire for every nested leaf subgroup.
- Prefix row-group scopes are also the aggregate scopes for nested headers, so `Sum`/`CountRows` can report category, region, and deeper constrained totals without introducing dataset traversal or an unsafe expression host.
- Composite row-group keys use structural sequence comparison rather than delimiter-concatenated strings, so legitimate field values containing the delimiter cannot merge unrelated tablix scopes.
- Group-expression discovery walks nested `TablixMember` containers in document order instead of scanning arbitrary descendants; the constrained renderer then uses that ordered list for prefix scopes while leaving member geometry explicit.
- Static v2 outputs honor the evaluated initial `Hidden` state even when RDLC includes `ToggleItem`; interactive expand/collapse is deferred until the shared document/canvas model can carry interaction state across backends.
- The Windows-only v1 bridge snapshots `RPLReport` page operations before releasing the legacy report context. `CreatePortableDocument` keeps the constrained RDLC engine as the first path and invokes RPL pagination only for `NotSupportedException`/`InvalidDataException`, preserving the legacy `Render` API and keeping RPL references out of portable packages.
- The constrained RDLC engine accepts one linear row-group branch and grouped `PageBreak/BreakLocation=Between`; branching `TablixMember` trees and `Start`/`End` group breaks are rejected explicitly until the shared page model can represent their semantics.
- The preview release checklist separates local API/security/documentation review from the unresolved System.Security.Cryptography.Xml advisories and licensing review; those remain stable-release blockers even though the portable package gate passes.
- Shareable test evidence is stored at `artifacts/test-results/ReportViewerCore.Rendering.Tests.trx`. The reusable artifact validator now checks the TRX, smoke outputs, and every source RDLC fixture plus its copied test-output fixture, so a feature cannot be considered covered when its fixture is empty, malformed, or absent from the test run.
- Keep fixture behavior discoverable in `tests/fixtures/README.md` as a coverage index. The validator checks exact source/output filename parity so stale or untested RDLC files cannot be mistaken for active regression coverage.
- Extend the constrained expression host only with pure, fixture-backed functions. `Len`, `Trim`, `UCase`, and `LCase` resolve one nested atom and never invoke report code or reflection-based methods.
- OpenXML capture retains the first page size so DOCX `w:pgSz` reflects the report instead of a hard-coded A4 section; XLSX worksheets expose a deterministic `dimension` range based on emitted cells.
- Empty tablixes honor a trimmed `NoRowsMessage` after the static header and before the empty-row fallback; the message uses the first row textbox font when available and remains a shared placement for every renderer.
- The expression host adds pure `InStr` and `Replace` only with fixed argument counts and current-culture string operations; malformed calls return empty and cannot invoke report code.
- Word OpenXML converts CR/LF text into explicit `w:br` nodes inside a styled run; Excel keeps its existing preserved-whitespace text path, and a fixture-backed Word assertion prevents newline loss.
- HTML SVG converts multiline text into positioned `tspan` nodes with deterministic line spacing, keeping line breaks visible instead of relying on browser whitespace handling.
- Existing engine pagination is now asserted at native OpenXML boundaries too: a multi-page simple RDLC fixture must produce a Word page break and multiple Excel workbook sheets, not only HTML page sections.
- HTTP report transport validates endpoint scheme and output format while constructing the request, before authentication or network I/O; unsupported values fail closed with no handler request.
- `NoRowsMessage` remains a backend-neutral placement: the fixture must assert its semantic text in HTML, PDF signature, SpreadsheetML, and WordprocessingML outputs.
- `ReportPageSourceAdapter` rejects zero-page sources and non-positive page dimensions before creating the portable document; these are explicit bridge contract failures rather than silent empty output.
- The 20-iteration loop remains bounded by an exit condition: local v2 behavior is considered complete only after the full suite, current smoke, fixture parity, and repacked package archives all validate; hosted Windows comparisons and major member-tree/layout redesign remain explicit follow-up work.
- The NU1903 `System.Security.Cryptography.Xml` warning is transitive through `System.ServiceModel.Primitives` from the legacy `System.ServiceModel.Http` compatibility/bridge line; the six portable v2 packages remain outside that dependency closure. Do not hide the warning or change dependency versions without a separate compatibility/security review.
- Rich v2 chart types use a backend-neutral `RenderChartType` contract with `Bar`, `Column`, `Line`, `Area`, `Pie`, and `Doughnut` values. The constrained RDLC engine allow-lists those six types; HTML/SVG, Skia/PDF, and OpenXML render semantic equivalents, while other chart types continue to fail explicitly.
- Top-level RDLC subreports are composed as page overlays alongside tablix and standalone body placements; the explicit resolver and nesting limit remain unchanged, while arbitrary subreports inside tablix cells still require a richer row-placement model.
- Shared `ReportDocument` validation rejects null draw delegates and non-positive/non-finite page sizes early; page-source adapters preserve their `InvalidDataException` boundary for malformed source dimensions.
- Word OpenXML emits page breaks only between pages, and PDF hyperlink annotations use both shaped advance axes so vertical links receive a clickable rectangle.
- Network-path hyperlinks beginning with `//` are rejected by the shared URL policy because they can redirect relative-looking links to an external host.
- Non-finite numeric chart values are excluded before entering the backend-neutral chart contract; unsupported nested subreport placements are rejected explicitly instead of being silently dropped.
- Tablix-cell visual items are traversed recursively so nested textbox/image/chart/shape coordinates accumulate cell, row, and container offsets consistently.
- Legacy bridge samples force a real v1 PDF render before reading page metadata and fall back to counting `/Type /Page` objects when the legacy `ExecutionInfo.TotalPages` value remains zero; both headless and WinForms bridge comparisons pass locally on Windows.
- Allow-listed comparison parsing must be quote- and parenthesis-aware; raw `IndexOf` matching can split inside a literal such as `"A=B"` and silently change report output.
- Reject non-finite font and direct Skia page/bitmap dimensions before native calls, and fall back empty RDLC font-family values to Arial so malformed layout inputs remain deterministic.
