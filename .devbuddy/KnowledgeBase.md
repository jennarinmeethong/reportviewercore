# KnowledgeBase

## Lessons

- Adding an `osx-arm64` RID alone cannot make this repository portable because the legacy rendering path directly invokes `usp10.dll`, `gdi32.dll`, `User32.dll`, `System.Drawing`, and `System.Drawing.Printing`.
- SkiaSharp and HarfBuzzSharp can be introduced without pulling System.Drawing into the new contract or backend projects. Keep generated smoke artifacts outside the repository and use explicit font registration for deterministic output.
- Treat font files as caller-owned inputs: the Skia resolver uses platform family matching by default, but an explicitly registered file must exist and load before rendering; do not silently substitute a missing registered asset.
- When mapping backend-neutral text into DOCX paragraphs, preserve `Baseline.X` with `w:ind`/twips; do not fake absolute Y placement with cumulative paragraph spacing because page order would amplify the offset.
- Use page-relative DOCX DrawingML anchors for images/charts when the backend-neutral operation has a destination rectangle; emit EMU position offsets and extents, and keep text paragraphs on the baseline/indent path.
- Test both sides of font policy: a normal family exercises platform fallback, an unknown family must throw `FontNotFoundException`, and a registered path must exist/load before use; do not infer that OpenXML family metadata embeds a font.
- For variable-size multi-page DOCX output, put `pgSz` inside a `nextPage` section break for every non-final page and use the final page's size in the body `sectPr`; a single first-page section silently mis sizes later pages.
- For OpenXML images crossing a page boundary, clip the destination before generating anchors and carry the removed fractions as DrawingML `srcRect` percentages; use a separate zero-permitting EMU conversion for origin offsets because positive-only extents must not shift an image by one EMU.
- For OpenXML vector clipping, intersect rectangles with the page and clip line parameters before rebuilding bounds; preserve clipped line start/end points because a bounding-box-only line silently changes reverse or diagonal geometry.
- Keep a comprehensive feature showcase separate from the minimal smoke sample: the showcase can evolve with new canvas features and a manifest validator without weakening the CI smoke artifact contract.
- A visual showcase can expose renderer defects that semantic/package validators miss; inspect generated PNG pages after changes. In particular, platform fallback shaping must emit per-glyph advances and Skia must split newline text before positioned-glyph rendering.
- Keep OpenXML text style conversion explicit: Word uses run fonts/half-points and Excel uses rich-text run properties; do not rely on the workbook default font when the backend-neutral `FontRequest` carries a family or weight.
- Running independent `dotnet run` builds concurrently can leave MSBuild contention that looks like a renderer hang; build once with shared compilation disabled, then invoke the compiled assembly for deterministic smoke validation.
- A portable CI job should publish every supported RID, but execute only on a runner with the matching architecture; `linux-arm64` can be publish-validated from an x64 hosted runner.
- The current RDLC parser is a deliberate vertical slice, not a replacement for RPL/SPB processing. Keep unsupported vector graphics, advanced charts, expressions, pagination, and server transport behavior explicit in docs and tests.
- Windows should consume the same `ReportDocument` and Skia renderer as other RIDs. Keep `System.Drawing` restricted to the WinForms display adapter, and mark runtime-only custom-control properties with `DesignerSerializationVisibility.Hidden` for the .NET 10 WinForms analyzer.
- Legacy bridge methods must read the direct report definition and data sources without `EnsureExecutionSession`; the legacy processor validates unsupported query metadata before the portable subset can render. Keep the bridge opt-in so v1 `Render` behavior is preserved.
- A legacy bridge must not call `EnsureExecutionSession()` merely to retrieve an RDLC definition; that invokes legacy validation and can reject definitions the portable subset intentionally accepts. Read the catalog definition directly and keep portable parameter capture separate from legacy `SetParameters`.
- Keep image resolution outside the engine: embedded bytes are parsed as `RenderImageRequest`, while external image access is supplied by the caller. This preserves headless security boundaries and avoids hidden network/file access.
- Resolve RDLC `Image.Value` expressions before creating the `RenderImageRequest`, so parameter/field-driven image keys reach the injected resolver while external fetching remains caller-controlled.
- Tablix image coordinates are relative to the cell and row template; resolve each image with the current data row before adding it to the shared page model, otherwise detail images lose both field values and repeated-row offsets.
- When a report body contains tablixes and standalone items, do not return early from the tablix path. Collect the non-tablix items into the same placement lists so mixed reports preserve all content across every backend.
- Skia PDF exposes URL annotations through `SKCanvas.DrawUrlAnnotation`; annotate after drawing shaped text and derive the rectangle from font metrics so the link follows the visible label.
- Mixed RDLC report items should be collected into one backend-neutral page model; avoid branching on the first item type, otherwise a chart can silently discard sibling textboxes/images/shapes.
- Subreport resolution must be explicit and bounded. Reuse the parent data context for the constrained v2 path, copy inherited parameters, and apply explicit `<Subreport><Parameters>` mappings; do not infer report file paths or network URLs from `ReportName`.
- Keep the HTTP server transport independent of authentication. Build URL-access queries deterministically, inject headers/tokens through the authenticator, and never enable ambient/default credentials on non-Windows hosts.
- Keep script coverage explicit in tests: Latin-only shaping can pass while Thai, Arabic/RTL, or CJK glyph runs regress due to font fallback or direction handling.
- Vertical shaping needs an explicit advance axis in the Skia fallback path; otherwise glyphs are returned but every glyph remains at the same baseline. Keep vertical direction assertions in the shaping and output tests.
- In this restricted desktop environment, VSTest can abort before test discovery with `SocketException (13): Permission denied` while binding its communication listener. Treat that as infrastructure evidence only; a successful targeted run before the restriction is the code-result evidence, and do not keep retrying the same command indefinitely.
- NuGet pack can wait on project-reference evaluation when MSBuild runs in parallel. Build once, then use `dotnet pack ... -m:1 -p:UseSharedCompilation=false`; metadata can be independently checked with `dotnet msbuild <project> -getProperty:PackageId -getProperty:VersionPrefix`.
- Excel direction output needs a styles part and workbook relationship; putting an `s` attribute on a cell without `xl/styles.xml` produces a structurally incomplete workbook. Use `textRotation=255` for vertical text, `90` for reverse vertical, and `readingOrder=2` for RTL.
- Page headers and footers are page-relative decorations. Collect them separately from body placements and append them to every generated page; otherwise a multi-page tablix only renders its header/footer on page one.
- Apply RDLC parameter defaults while creating a case-insensitive parameter dictionary, then overlay caller values first; this preserves explicit values even when expression casing differs from the report definition.
- RDLC `ActionInfo/Hyperlink` belongs on the backend-neutral text placement, not in a renderer-specific parser. Resolve parameter/field expressions at engine time and let HTML/PDF/OpenXML enforce their own URL policy.
- Nested RDLC report items require recursive collection with accumulated parent `Left`/`Top`; collecting all descendants flatly loses rectangle/container offsets.
- Keep text style metadata on the engine placement (`Color`, `TextDirection`) so every renderer receives the same semantics; do not bake RDLC `WritingMode` parsing into HTML or Skia alone.
- Keep expression evaluation deliberately allow-listed: resolve quoted string literals and top-level `&` concatenation around field/parameter references, but do not execute arbitrary RDLC code while the portable engine lacks the full SSRS expression host.
- OpenXML shape operations can be captured as backend-neutral rectangles/lines and emitted as Excel DrawingML shapes plus Word VML fallbacks; keep advanced geometry explicit until the shared contract grows beyond basic shapes.
- A line cannot be represented faithfully by only its bounding box: preserve start/end orientation when adapting it to DrawingML or VML, especially for reverse diagonals.
- Use `IReportPageSource` as the RPL/SPB boundary: adapt page count, page size, and page rendering into `ReportDocument` without referencing legacy pagination classes from portable packages. The concrete v1 RPL traversal remains host-specific.
- Keep `IIF`, comparisons, and `Format` allow-listed and string-oriented. This gives common report templates useful behavior without reintroducing the unsafe full SSRS expression host.
- Boolean composition is safe to add only as explicit `Not`/`And`/`Or` atoms over the existing condition resolver; `IsNothing` should return empty for unsupported operands instead of silently treating them as null.
- Apply tablix sorting to materialized data rows before row expansion and page splitting. Compare numeric keys numerically and fall back to culture-aware text comparison so `10` sorts after `2` numerically.
- Evaluate `CountRows`, `Sum`, and `Avg` against the materialized current tablix rows and pass that scope through text placement evaluation; body text without a tablix scope must remain empty for these aggregates.
- For constrained grouped tablixes, partition the sorted rows by the first `TablixRowHierarchy/GroupExpressions/GroupExpression` and pass each group list as the aggregate scope. Full nested member/header/subtotal rendering remains outside this slice.
- Numeric `Min` and `Max` should use the same materialized group scope and numeric parsing as `Sum`/`Avg`; do not silently compare formatted strings.
- When a grouped tablix has three or more row templates, treat the middle template as the first-level group header and the final template as detail. This matches the common static-header/group-header/detail layout without guessing at nested member geometry.
- With four or more templates in the constrained grouped layout, use the penultimate template for detail and the final template for the group footer/subtotal. Pass the last row in the group as the footer data row so field labels and scoped aggregates both resolve.
- Multiple group expressions use an order-preserving composite key. This provides correct aggregate scope for common Category+Region layouts while leaving nested group-header geometry explicit.
- For the two-level constrained layout, the first group key renders the outer header once, the composite key renders the inner header per subgroup, then detail and footer rows use the composite scope. Deeper member trees still require a richer page model.
- For three or more constrained row-group levels, compute prefix scopes from the materialized sorted rows and render each header only when its ordered prefix changes; keep the row-template convention explicit instead of inferring arbitrary recursive member geometry.
- Track accumulated row heights instead of multiplying a row index by the current template height; this is required for reliable grouped page breaks when header/detail/footer heights differ.
- Prefix scopes must carry their complete materialized row lists into header placement; that makes nested `Sum`, `CountRows`, and similar aggregates resolve at the correct group level.
- Read RDLC group expressions by recursively walking `TablixMembers`; broad descendant scans can accidentally treat unrelated nested XML as row-group levels and lose hierarchy order.
- Do not invent toggle interaction inside a draw-only canvas. For static HTML/PDF/OpenXML/Skia output, evaluate the initial `Hidden` expression and defer expand/collapse metadata to an explicit interaction contract.
- NuGet pack warnings for missing README/symbols are release-gate failures, not cosmetic noise; set `PackageReadmeFile`, `IncludeSymbols`, and `SymbolPackageFormat` on each v2 project, then inspect both `.nupkg` and `.snupkg` archives.
- If a package README links to migration documentation, include the linked checklist at the package root too; otherwise the NuGet page renders a broken relative link even when the README warning is gone.
- RID restore assets are selected per restore and overwrite the shared `project.assets.json`; restore and publish each matrix RID together when validating locally, matching the CI workflow.
- Legacy bridge samples should fail the Windows job on semantic/page-count mismatches, and their generated HTML should be uploaded so RPL fallback differences remain inspectable after CI completes.
- RPL page and text/tablix queues are lazy and destructive (`GetNextReportSection`, `GetNextRow`, `GetNextParagraph`, and `GetNextTextRun`). A portable adapter must materialize operations during construction; rendering directly from those queues would make a second backend render or bitmap preview lose content.
- RPL measurements are millimetres while the v2 samples/PDF use point-like canvas units. Convert page and item geometry with the legacy `72 / 25.4` relationship at the adapter boundary, and decode embedded/dynamic image bytes through `SkiaImageCodec` before releasing the RPL context.
- The constrained RDLC expression host now allow-lists scoped `Count`, `First`, and `Last` alongside the existing aggregate functions; keep adding expression forms only with focused fixtures and security review.
- Visibility should be evaluated at the engine placement boundary, before image resolution or text placement, so hidden standalone items and tablix-cell content do not trigger caller-provided resource access.
- Release archive checks should inspect every `.nupkg`/`.snupkg`, not only one representative package: a Portable PDB reader confirmed SourceLink data and three EmbeddedSource records in each of the seven v2 symbol archives.
- Golden bridge expectations should be shared by the headless and WinForms samples so page-count and required semantic text drift fails both hosted smoke paths consistently.
- The headless legacy bridge sample can render its constrained portable output on macOS, but the legacy `GetTotalPages` path reports zero there; keep the legacy-vs-v2 page-count assertion Windows-only and continue checking golden portable semantics on non-Windows hosts.
- The local Apple Silicon host has no Rosetta x64 .NET runtime (`arch -x86_64 dotnet` returns `Bad CPU type`), so `osx-x64`, Linux, and Windows native smoke must be verified on their matching CI runners.
- Grouping tests should include null-key rows and empty data regions: the constrained engine normalizes null field values to an empty group key, preserves aggregate scope for those rows, and still emits static tablix headers when no groups materialize.
- Culture-specific numeric sort fixtures should set the test's current culture explicitly and restore it in `finally`; the engine compares decimal-comma strings numerically through the active culture.
- Multi-value parameter support stays allow-listed: expose collection formatting only through `Join(Parameters!Name.Value, separator)`, rather than executing arbitrary collection expressions or stringifying arrays as CLR type names.
- Keep a negative security fixture for unsupported `Code.*` expressions: the constrained engine should render the safe surrounding text and an empty unsupported atom without invoking user report code.
- Tablix-cell charts, rectangles, and lines must be added with the cell-column and repeated-row offsets; otherwise the backend contract supports the visual item but the RDLC engine silently drops it.
- Preview release docs should distinguish the new v2 package line from unchanged legacy behavior and state the unsupported parity/security boundaries next to the migration instructions.
- Multi-value RDLC defaults must preserve every `<DefaultValue>` as a collection before `Join` evaluation; scalar parameters continue to use the first default value.
- Dependency audits must exclude the intentional Windows adapter when checking portable package closure; the six cross-platform packages stay free of Windows desktop/System.Drawing dependencies.
- Unsupported RDLC Map, GaugePanel, and CustomReportItem nodes should fail explicitly in the constrained engine instead of being silently dropped; this keeps migration gaps observable and safe.
- Constrained chart support now allow-lists bar, column, line, area, pie, and doughnut through the shared `RenderChartType` contract; reject radar and other chart types until their geometry and semantics are explicitly modeled.
- The legacy compatibility projects directly pin `System.Security.Cryptography.Xml` 10.0.10, and their nuspecs mirror that dependency for net8/net9/net10; verify restore/build and package metadata before treating the advisory as closed. Licensing/legal review remains separate.
- Keep `IsNothing` allow-listed and null-focused: resolve only field/parameter atoms and do not turn it into a general-purpose expression evaluator.
- A flattened `TablixMember` walk cannot faithfully render sibling row-group branches or `PageBreak` locations such as `Start`/`End`; reject those shapes before pagination instead of silently treating them as a linear group or a `Between` break.
- A tablix `PageBreak=Between` belongs to its group scope, not the whole tablix. Compare the relevant prefix key before advancing pages so inner group transitions do not inherit an outer break accidentally.
- Excel hyperlink relationship order must be derived from the same row/column placement list as worksheet cells; draw order alone can point a later-row hyperlink at the wrong cell reference.
- Merged-cell metadata must travel with semantic table-cell operations rather than being inferred from text positions. Keep the default canvas fallback for compatibility, and have OpenXML derive merge ranges and worksheet dimensions from the explicit cell origin and spans.
- OpenXML text with leading or trailing whitespace needs `xml:space="preserve"` in both SpreadsheetML and WordprocessingML text nodes; otherwise package consumers may normalize visible spacing.
- Release checklists should split completed local compatibility/security-boundary review from dependency advisories and legal review; a green build/package gate does not clear those external release blockers.

- Sibling RDLC row groups are separate tree structures, not extra flattened group-expression levels. The constrained engine can safely render dynamic sibling trees with an explicit static-header/group-header/detail row contract, shape-based template indexes, trailing static subtotal rows scoped to the parent group, and one optional root-level trailing total row scoped to all tablix rows; branch-level `Between` page breaks are applied while other static children, footers, break locations, and ambiguous layouts remain rejected.
- For sibling branch `PageBreak/BreakLocation=End`, apply the page boundary before the next non-empty group scope instead of after the final group; this preserves end-break intent without manufacturing an empty trailing page.
- For sibling branch `PageBreak/BreakLocation=Start`, apply the boundary before every non-empty group instance, including the first; this matches RDL group semantics while keeping the constrained implementation deterministic.
- When a sibling branch with `End` or `StartAndEnd` is followed by a static member or root total, apply the boundary after the branch returns and before that following row; otherwise a nested page-break test can pass while the subtotal/total is incorrectly kept on the prior page.
- Shape-based sibling template indexes can safely place a static child row before or after a dynamic child branch when the row hierarchy and row-template contract are explicit; keep ambiguous interstitial root layouts rejected.
- Root sibling template indexes can also include an explicit static member between dynamic branches when that member is represented by one row template and the surrounding member order is unambiguous; retain the leading static header and reject malformed or unsupported member trees.
- A static member with nested children needs its own row template before recursively indexed child templates; treating it as a leaf silently drops the wrapper row and shifts every following sibling template.
- Child `End` boundaries inside a static wrapper must be applied in the wrapper's child loop before the following static subtotal; checking only the wrapper node cannot observe the nested group break.
- Recursive member indexes remain deterministic when a static wrapper contains dynamic, static, and dynamic children in that order; each child contributes its own template shape before the following sibling is resolved.
- A nested child `StartAndEnd` break is evaluated within the wrapper's scoped child loop, so each non-empty child scope starts on a fresh page and transitions to the next child scope without adding a trailing page after the wrapper.
- A single root group can use the sibling renderer when its nested member tree contains an explicit sibling split; keep ordinary one-level groups on the linear path to preserve their existing template convention.
- Sibling row-group templates do not require a leading static header; calculate optional leading/trailing static members independently so reports that begin directly with dynamic group headers retain their row-template indexes.
- Exercise optional sibling-header indexing at both root and nested-member levels; a top-level no-header test does not prove recursive template offsets remain correct.
- Console bridge samples should catch top-level exceptions, print the full exception to stderr, and return exit code 1; otherwise Windows apphost displays only the opaque 0xe0434352 application-error dialog.
- Linear nested RDLC page breaks need separate start and transition sets: `Start`/`StartAndEnd` must be evaluated for the first scope after static content, while `Between`/`End` boundaries should be applied only when the relevant group prefix changes to avoid empty trailing pages.
- When a dynamic nested member contains only static leaf members, rendering each child once loses all but the first data row. Treat the first static leaf as the repeated detail template and subsequent leaves as scoped footer rows; keep mixed dynamic/static children on the recursive branch path.
- The reusable artifact validator can be run after local pack/test/smoke generation: the current v2 gate passes 7 `.nupkg`, 7 `.snupkg`, 109 TRX outcomes, 55 copied RDLC fixtures, and seven-file smoke directories; local `win-x64` execution now passes, while matching-RID hosted execution remains a separate confirmation.
- Nested member routing should be shape-gated: a single-child static wrapper is safe to recurse only when `CountGroupMemberTemplates` exactly matches the available row templates; otherwise preserve the existing linear fallback rather than misclassifying a root total as a group footer.
- The same shape gate covers static wrappers with multiple nested dynamic children and scoped leading/trailing rows; add a fixture before broadening the recursive contract so row-template offsets and root totals remain observable.
