# Cross-platform v2 status

The constrained expression host now keeps quoted-literal comparisons safe and allow-lists `Mid`; direct Skia bitmap/PDF entry points reject non-finite dimensions, and empty RDLC font-family values use the deterministic Arial fallback.

For the complete next-session checklist and phase plan, see [`cross-platform-v2-checklist.md`](cross-platform-v2-checklist.md).

The repository now contains the first portable rendering boundary:

- `ReportViewerCore.Rendering.Abstractions` owns backend-neutral geometry, font, text, image resolver, chart, canvas, and document contracts.
- `ReportViewerCore.Rendering.Skia` implements PNG/image, PDF, font metrics, HarfBuzz text shaping, platform-font fallback advances, and native multiline text using SkiaSharp and HarfBuzzSharp.
- Font resolution uses the platform font manager by default; callers may register an explicit font file for deterministic shaping, missing registered files fail before rendering, and unknown families fail closed. Fonts remain caller-owned; OpenXML references the requested family but does not silently embed or substitute font bytes. Matching-RID fallback coverage remains a CI concern.
- `ReportViewerCore.Rendering.Html` emits standalone SVG-backed HTML with escaped text, shared-policy-safe hyperlinks, and embedded PNG images.
- `ReportViewerCore.Rendering.OpenXml` emits valid XLSX and DOCX packages with multi-page text, per-page DOCX section sizes and page breaks, font family/size/weight/style and color metadata, preserved leading/trailing whitespace, horizontal text offsets, page-relative floating image/chart anchors with preserved extents, page-clipped image anchors with source crop metadata, page-clipped rectangle/line shape parts with preserved visible endpoints, correctly oriented line shapes, correctly placed external hyperlinks, embedded PNG image parts, native rectangle/line shape parts, and native bar/column/line/area/pie/doughnut chart parts.
- `ReportViewerCore.Engine` now parses tested RDLC multi-tablix, explicit subreport, page header/footer, textbox hyperlinks, nested report items, and styled text, plus mixed textbox/image/rectangle/line/bar/column/line/area/pie/doughnut-chart report-item paths; it keeps non-tablix body items alongside tablixes, applies tablix `SortExpressions` before pagination, traverses nested `TablixMember` group expressions in document order, renders constrained three-or-more-level row-group headers plus group-footer/subtotal templates when matching row templates are present, repeats the first static leaf under a linear dynamic member as detail and emits later static leaves as scoped footers, applies grouped `PageBreak` metadata only when the page-break member's scope prefix changes while honoring linear `Between`/`Start`/`End`/`StartAndEnd` locations, evaluates prefix-scoped `CountRows`, `Count`, `First`, `Last`, `Sum`, `Avg`, and `Min`/`Max`, applies allow-listed conditional visibility to standalone items and tablix-cell text/images, preserves the initial `Hidden` state for static `ToggleItem` reports, applies parent offsets including tablix-cell visual items, binds `IEnumerable` rows, maps color/writing mode, applies RDLC parameter defaults including multi-value defaults without overriding caller values, expands allow-listed field/parameter expressions including string concatenation, `IIF`, comparison, `Format`, `IsNothing`, boolean `Not`/`And`/`Or`, and multi-value `Join`, resolves expression-driven and embedded images in body and tablix cells through an injected `IImageResolver`, and splits overflowing rows into `ReportDocument` pages.
- `ReportViewerCore.Headless.LocalReport` exposes the first v2 local workflow; `ServerReport` exposes an explicit `IReportServerTransport` boundary, with `HttpReportServerTransport` providing URL-access rendering and caller-injected authentication.
- `ReportViewerCore.Engine` also exposes `IReportPageSource`/`ReportPageSourceAdapter` as the RPL/SPB migration seam: a legacy pagination adapter can render each page into the same `ReportDocument` consumed by every backend without leaking legacy or System.Drawing types.
- Shape-matched recursive member trees now cover static wrappers with multiple nested dynamic children, scoped leading/trailing rows, and root totals; layouts without a deterministic row-template contract remain constrained. The constrained linear group implementation supports grouped `PageBreak` locations `Between`, `Start`, `End`, and `StartAndEnd`; unsupported branching/member layouts are rejected rather than silently producing incorrect layout.
- Supported sibling branches also accept `PageBreak/BreakLocation=Start`, `End`, and constrained `StartAndEnd` by placing branch groups and supported following static totals at explicit page boundaries; linear groups and other break locations retain their existing constrained behavior.
- The net10 WinForms bridge now snapshots legacy `RPLReport` pages into that seam when the constrained RDLC engine rejects a report. The Windows-only adapter maps page sections, containers/tablixes, text styles and hyperlinks, images, dynamic chart/map streams, lines, rectangles, and page decorations; v2 still owns PDF/HTML/OpenXML/Skia output after the fallback.
- `ReportViewerCore.Headless` selects an injected renderer for a backend-neutral `ReportDocument`; it does not depend on System.Drawing.
- `ReportViewerCore.Rendering.Windows` is a Windows-only WinForms display adapter. It displays pages rendered by the same SkiaSharp backend; it does not introduce a second GDI report renderer. `Microsoft.ReportViewer.WinForms` exposes this as the explicit net10-only `PortableReportViewer` control while retaining the legacy `ReportViewer` control.
- `ReportViewerCore.Sample.CrossPlatform` is a native smoke sample that writes PNG, PDF, HTML, XLSX, DOCX, and RDLC-engine output.
- `ReportViewerCore.Sample.FeatureShowcase` is the executable acceptance example: it renders a two-page document using every positive canvas feature and a bundled RDLC definition covering the constrained engine path. It exports page PNGs, PDF, HTML, XLSX, DOCX, source RDLC, and manifests for both coverage sets.
- `ReportViewerCore.Sample.WinForms.V2` demonstrates the Windows adapter with the same `LocalReport`/RDLC workflow.
- `ReportViewerCore.Sample.LegacyBridge` demonstrates the explicit `Microsoft.Reporting.NETCore.LocalReport.RenderPortable` bridge for existing Windows applications and asserts semantic rows plus portable-vs-legacy page count.
- `ReportViewerCore.Sample.WinForms.LegacyBridge` verifies the equivalent `Microsoft.Reporting.WinForms.LocalReport` bridge on Windows, including an explicitly loaded subreport that forces the RPL fallback and checks propagated text/page count.
- `tests/ReportViewerCore.Rendering.Tests` verifies the backend without loading `System.Drawing`, including Thai, Arabic/RTL, CJK and vertical shaping, body/tablix images and image expressions, composite/function/aggregate expressions, sorted/grouped tablixes, charts, links, subreports, multi-tablix layout, and OpenXML package parts.
- The seven v2 libraries have explicit NuGet identities and share the `2.0.0-preview.1` package line. Their package metadata includes the cross-platform migration README, linked checklist, symbol packages, and repository metadata; pack them individually into a release artifact directory and validate the archives before publication. Legacy package identities are intentionally unchanged.

CI runs the portable tests and sample publish for `linux-x64`, `linux-arm64`, `osx-arm64`, `osx-x64`, and `win-x64`. Local release validation has published all five RID payloads, with native execution completed for `osx-arm64` and `win-x64`; a separate Windows job builds the WinForms v2 adapter and both legacy bridge samples, then executes the bridge smoke tests against shared golden semantic/page-count expectations. The headless bridge can validate portable semantics on non-Windows hosts, but its legacy page-count comparison is Windows-only because the v1 processor reports no pages off Windows. Native smoke execution runs on matching hosted runners; the `linux-arm64` job validates restore and publish without trying to execute an ARM binary on an x64 runner.

This is an incremental migration. The legacy `Microsoft.ReportViewer.NETCore` and `Microsoft.ReportViewer.WinForms` packages remain compatibility lines and still contain the old GDI/System.Drawing/RPL path, while net10 callers can opt into v2 with `CreatePortableDocument`/`RenderPortable`; the old `Render` path is unchanged. On WinForms, `CreatePortableDocument` first uses the constrained engine and only invokes legacy RPL pagination for unsupported/invalid constrained input. New Windows applications should use the v2 headless API plus `ReportViewerCore.Rendering.Windows`; the WinForms adapter is display-only and receives backend-neutral pages. Subreports use an explicit resolver, support parent-to-child parameter mappings, and have a nesting guard; top-level subreports can be composed alongside tablix/textbox body content, while subreports inside tablix cells or nested containers fail explicitly until the page model supports their placement semantics. The RPL/SPB seam is now an explicit page-source adapter, while shape-matched recursive grouped tablixes render static wrappers, nested dynamic children, scoped leading/trailing rows, nested headers, subtotals, composite group scopes, and basic visual items inside cells. Unrestricted member layouts, advanced chart/map contracts, printer output, and golden legacy-vs-v2 comparison remain separate compatibility tasks. Do not load untrusted RDLC sources; arbitrary report code is intentionally not executed by the constrained expression host.

The legacy compatibility packages directly pin `System.Security.Cryptography.Xml` `10.0.10` in both project and nuspec dependencies, overriding the vulnerable transitive floor from `System.ServiceModel.Primitives` without changing the v1 API/rendering path. The six portable v2 packages do not include that dependency. Complete the remaining licensing/legal review before calling the preview line stable.

Use the smoke sample from the repository root:

```bash
dotnet run --project ReportViewerCore.Sample.CrossPlatform -- ./artifacts/cross-platform
```

Export and validate the full feature showcase after each implementation change:

```powershell
dotnet run --project ReportViewerCore.Sample.FeatureShowcase -- ./artifacts/feature-showcase
python .devbuddy/tools/validate_v2_artifacts.py --showcase ./artifacts/feature-showcase
```

The output directory is intentionally caller-controlled so generated artifacts do not pollute the repository. The sample also writes `rdlc-engine.html` and `rdlc-engine.pdf` from the bundled RDLC/data fixture. HTML, PDF, and OpenXML links allow only relative, `http`, `https`, and `mailto` URLs. DOCX/XLSX use a Skia-rasterized page preview as their visible layer so Office rendering matches PNG/PDF/HTML layout; native text, hyperlinks, images, shapes, and charts remain in hidden or off-viewport OpenXML parts for semantic compatibility. OpenXML preserves vertical/RTL text through native styles, maps constrained RDLC tablix `ColSpan`/`RowSpan` metadata to bounded merged-cell ranges, emits per-page DOCX section sizes and page-relative floating anchors for images/charts, clips page-crossing images with native source-crop metadata, clips page-crossing rectangles/lines to visible geometry, and maps basic rectangles/lines plus bar/column/line/area/pie/doughnut charts; text/chart clipping, unsupported chart kinds, and full chart/RPL/SPB mapping are later phases.

Run the local equivalent of the portable gate with `dotnet test tests/ReportViewerCore.Rendering.Tests --results-directory ./artifacts/test-results --logger "trx;LogFileName=ReportViewerCore.Rendering.Tests.trx"` and `dotnet publish ReportViewerCore.Sample.CrossPlatform -r osx-arm64 --self-contained false`. The TRX report is written to `./artifacts/test-results/ReportViewerCore.Rendering.Tests.trx`; compiled test binaries remain under `tests/ReportViewerCore.Rendering.Tests/bin/<Configuration>/net10.0/`. Validate the saved test evidence with `python3 .devbuddy/tools/validate_v2_artifacts.py --test-results ./artifacts/test-results/ReportViewerCore.Rendering.Tests.trx` and validate that every RDLC fixture has content and reaches the test output with `python3 .devbuddy/tools/validate_v2_artifacts.py --fixtures ./tests/fixtures/engine --fixture-output ./tests/ReportViewerCore.Rendering.Tests/bin/Debug/net10.0/fixtures/engine`.
For a local v2 package smoke, run `dotnet pack ReportViewerCore.Headless/ReportViewerCore.Headless.csproj -c Release -o ./artifacts/nuget-v2 -m:1 -p:UseSharedCompilation=false` and repeat for the other `ReportViewerCore.*` v2 library projects.
